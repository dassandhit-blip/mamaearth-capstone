# Mamaearth Returns & Growth Intelligence Pipeline

Capstone project - Data Analytics with AI & Gen AI (E&ICT Academy IIT Roorkee).

**Business question:** returns are suspected of eating into margins on a subset of orders. This repo
proves it end to end with three connected layers: a **SQL** store, a **Python/pandas** analysis
layer, and a **GenAI** narrative layer for regional ops and finance heads.

**Golden rule:** no layer reports a number it did not compute itself or receive from the layer before it.

## How the layers connect

```
data/*.csv --(load)--> [1] SQL layer      sql/schema.sql, seed_data.sql, reports.sql
data/*.csv --(read)--> [2] Python layer   analysis/clean_and_eda.py, visualize.py
                                              |  writes verified numbers
                                              v
                                          narrator/findings.json
                                              |  read by
                                              v
                                       [3] GenAI layer    narrator/generate_narrative.py
```

- Layer 1 and Layer 2 both start from the same raw CSVs, so they can be run in either order.
  Layer 2 deliberately does not read the SQL database; it is an independent check on Layer 1
  (Layer 2 reconciles its cleaned revenue against Layer 1's raw revenue).
- Layer 2 -> Layer 3 is a hard dependency: `findings.json` must exist before the narrator runs.

## Setup

Python 3.9+ is needed for Layers 2 and 3. Run every command below from the **repository root**.

```bash
pip install pandas matplotlib          # Layer 2
pip install google-genai               # Layer 3, only needed for the online Gemini path
```

## Step 1 - SQL layer (Part 1)

Works in MySQL (MySQL Workbench) or SQLite.

1. Create and select a database, e.g. in MySQL: `CREATE DATABASE mamaearth_returns; USE mamaearth_returns;`
2. Run `sql/schema.sql` - creates the three tables (it drops them first, so it is re-runnable).
3. Run `sql/seed_data.sql` - loads the data. Check the counts: **45** customers, **16** products, **180** orders.
4. Run `sql/reports.sql` - the nine report queries (a to i). The exact output of each query is pasted
   as a comment above it. Query (i) alters the `customers` table, so re-run steps 2 and 3 before
   running the file a second time. In MySQL Workbench, if the `UPDATE` without a `WHERE` is blocked by
   safe update mode, run `SET SQL_SAFE_UPDATES = 0;` first.

SQLite alternative: `sqlite3 mamaearth.db < sql/schema.sql`, then `< sql/seed_data.sql`, then `< sql/reports.sql`.

## Step 2 - Python analysis layer (Part 2)

```bash
python analysis/clean_and_eda.py
python analysis/visualize.py
```

1. `clean_and_eda.py` reads the raw CSVs in `data/`, prints every intermediate result, and covers
   Tasks 1-10: load, standardise `payment_method`, drop the 5 duplicate orders, impute missing
   values, merge and reconcile against Part 1, IQR outliers, hypothesis test, segmentation,
   correlations and the outlier-corrected monthly series.
2. **Its final step writes `narrator/findings.json`** (carrying the reconciled revenue figures from
   Task 5 and the other verified numbers). The file is generated by code, never typed by hand,
   so it cannot drift from the analysis.
3. `visualize.py` recomputes the numbers from the raw CSVs and saves the two PNGs in `visualizations/`.

## Step 3 - GenAI narrator (Part 3)

```bash
python narrator/generate_narrative.py
```

The script reads `narrator/findings.json` and writes a Situation / Complication / Resolution narrative.
It then prints a PASS/FAIL line for each of the five key figures.

**Option A - with a Gemini API key (online path).** Get a free key from Google AI Studio
(https://aistudio.google.com, "Get API key"). The free tier is enough; no paid key is needed.
Set it as an environment variable, then run the script:

```bash
# macOS / Linux
export GEMINI_API_KEY="your-key-here"
# Windows PowerShell
$env:GEMINI_API_KEY="your-key-here"
# Windows cmd
set GEMINI_API_KEY=your-key-here

python narrator/generate_narrative.py --save-sample   # also saves narrator/sample_output.txt
```

The model call uses `temperature=0.0`, an explicit `max_output_tokens`, a 30-second timeout, and a
`try/except` that returns a structured dict instead of raising.

**Option B - no key at all (offline path).** Just run `python narrator/generate_narrative.py` with
`GEMINI_API_KEY` unset. The script prints an `[info]` line and switches to a deterministic template
built directly from `findings.json`: no network, no key, no configuration. The same fallback triggers
automatically if the API call fails.

**Numeric accuracy check.** Whichever path produced the narrative, the checker asserts these five
figures are present: `97,358.30` (cleaned revenue), `44.4` (COD return rate), `54.5` (COD + Tier-2
segment), `2,501.90` (duplicate delta), and `March` with `20,318.90` (true peak month). LLM output is
not byte-identical between runs, so the Gemini result is saved once to `narrator/sample_output.txt`
and the checker is also run against that saved file.
